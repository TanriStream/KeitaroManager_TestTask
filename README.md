# Keitaro Manager
## Что это?
Frontend-прототип приложения для создания и редактирования рекламных кампаний в Keitaro.
Основная цель - предоставить интерфейс для управления кампаниями, потоками и офферами через Keitaro API.

## Текущий статус проекта
**Frontend - backend в разработке.**

На текущем этапе реализованы две основные страницы / модальные окна:
- Создание рекламной кампании.
- Редактор существующих кампаний.

Полноценная интеграция с Keitaro Admin API пока не завершена из-за проблемы с доступностью предоставленного сервера.
При попытке открыть административную панель по адресу `https://tlgk.host/admin` сервер возвращает:
403 Forbidden
nginx

Из-за этого не удалось проверить доступность API, получить реальные данные и протестировать взаимодействие с Keitaro.

Поэтому текущая версия является frontend-прототипом. Фактическое создание кампаний, получение потоков и изменение офферов через Keitaro пока не реализованы.

## Функциональность
### 1. Создание кампании
Страница создания кампании содержит следующие поля:
- Название кампании.
- GEO-код страны.
- ID оффера.
- Домен.
- Группа кампании.
- Источник трафика.

Планируемая логика создания кампании:
1. Получение доступных доменов, групп и источников трафика из Keitaro.
2. Создание кампании с указанными параметрами.
3. Создание двух потоков:
   - Первый поток принимает пользователей из указанного GEO и перенаправляет их на Google.
   - Второй поток принимает оставшийся трафик и перенаправляет его на выбранный оффер.
**Текущий статус:** интерфейс реализован, интеграция с API ожидает восстановления доступа к Keitaro.

### 2. Редактор кампаний
Страница редактора содержит:
- Выбор существующей кампании.

Планируемые возможности редактора:
- Получение потоков выбранной кампании.
- Отображение офферов внутри потоков.
- Добавление и удаление офферов.
- Пересчёт весов офферов.
- Закрепление веса оффера (Pin).
- Восстановление удалённых офферов.
- Отмена локальных изменений.

### Установка и запуск
## Требования
- Python 3 (для запуска http сервера)

### Запуск frontend
1. Клонировать репозиторий:
git clone <ссылка на репозиторий>
2. Перейти в директорию frontend:
cd <папка-проекта>/src/frontend
3. Запустить локальный HTTP-сервер:
python -m http.server 5500
4. Открыть приложение/сайт в браузере:
http://127.0.0.1:5500

При запуске автоматически открывается страница создания кампании.
Для переключения между страницами используются кнопки навигации.

### Навигация
Для переключения страниц используется простой JavaScript-маршрутизатор на jQuery.
- `create.html` загружается по умолчанию.
- `edit.html` загружается при переходе в редактор кампаний.
- Переключение страниц происходит без полной перезагрузки приложения.

### Интеграция с Keitaro API
В дальнейшем приложение будет взаимодействовать с Keitaro Admin API.
Для авторизации предполагается использование API-ключа через HTTP-заголовок `Api-Key`.
Для полноценной работы потребуются методы получения:
- Доменов.
- Групп.
- Источников трафика.
- Офферов.
- Кампаний.
- Потоков кампаний.

**Важно:** интеграция с предоставленным экземпляром Keitaro пока не проверена из-за ответа `403 Forbidden (nginx)` от административного сервера.

API-ключи и другие учётные данные в репозиторий не добавляются.

### План дальнейшей разработки
После восстановления доступа к Keitaro планируется:
1. Реализовать backend-интеграцию с Keitaro Admin API.
2. Реализовать получение доменов, групп, источников трафика, офферов и кампаний.
3. Реализовать создание кампании с двумя потоками.
4. Реализовать получение и отображение существующих потоков.
5. Реализовать добавление, удаление и восстановление офферов.
6. Реализовать корректный пересчёт весов с учётом закреплённых значений.
7. Добавить отслеживание локальных изменений и возможность их отмены.
8. Реализовать отправку изменений в Keitaro.
9. Протестировать полный цикл работы с реальным экземпляром Keitaro.

### Безопасность (Рекомендации по деплою)

- Не следует размещать API-ключи в frontend JavaScript.
